# OpsPilot v1.2 Release Record

Release date: 14 August 2026

Version: `1.2.0`

Status: locally complete and verified

## Release Goal

v1.2 turns OpsPilot into a recruiter-readable portfolio release. It adds useful AI without giving it launch authority, persists operational analytics instead of hardcoding charts, and makes application failures visible as product evidence.

## Delivered

### Grounded optional AI

- Workspace feature flag plus server-side provider configuration check.
- OpenAI Responses API integration using strict structured output.
- Application-side schema, field, duplicate-key and evidence-key validation.
- Persisted provider, model, latency, token and input/output evidence.
- Explicit manager confirmation or rejection of valid AI proposals.
- Deterministic no-key/error fallback with an audited reason.
- Five committed contract and grounding evaluation fixtures.

### Operational analytics

- Workspace-scoped daily PostgreSQL snapshots.
- Seven-, fourteen- and thirty-day views for readiness, launch confidence, media and webhook reliability.
- Manager-authorised snapshot refresh and role-readable CSV export.
- Error and recommendation-run reliability counters.

### Error evidence and portfolio package

- Authenticated browser error capture and API 5xx capture with fingerprints and trace IDs.
- Manager triage and audited resolution; analyst mutation remains forbidden.
- Responsive `/analytics` workspace and public `/case-study` route.
- Real product screenshot, updated OpenAPI contract, ADRs, evaluation evidence and demo script.
- A verified 4 minute 32 second narrated 720p product walkthrough.
- CI environment corrected to start PostgreSQL, Redis and MinIO dependencies.

## Known Boundaries

- No API key is committed. The seeded public demo deliberately shows deterministic fallback.
- Evaluation fixtures verify contract and grounding controls, not general factual quality.
- Analytics use daily operational snapshots, not attendee-level event analytics or a warehouse.
- Error reporting is first-party persistence, not a replacement for hosted alerting and tracing.
- AI confirmation records human acceptance but does not execute arbitrary model-authored actions.
- The public case study is designed for local or deployed portfolio use; deployment remains environment-specific.

v2.0 is optional product expansion: adaptive streaming, live-session control, realtime updates, Portal Hub and engagement workflows. v1.2 is already the application-ready portfolio release.
