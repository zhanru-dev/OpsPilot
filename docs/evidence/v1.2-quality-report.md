## Accessibility and Responsive Evidence

Playwright runs axe-core on login, dashboard, Launch Control, Integration Centre and Analytics. No serious or critical findings were returned in the release run.

The suite checks root width at `390 x 844` across Overview, Events, Media Library, Integration Centre and Analytics. A separate visual review covered the public case study at `1440 x 900` and `390 x 844`. No root overflow remained.

The first mobile Analytics review did expose long evaluation identifiers widening a grid track to 476 pixels. The panels now use an explicit zero minimum width and technical identifiers wrap; the route was then added to the permanent browser regression test.

## CI and Reproducibility

`.github/workflows/ci.yml` installs from the lock file, starts PostgreSQL, Redis and MinIO, applies migrations and seed data, then runs lint, type checking, unit tests, API integration, production build, dependency audit and Playwright.

No remote CI run or badge is claimed because this release was intentionally kept local. The workflow becomes externally visible when the user chooses to publish the repository.

## Residual Risk

- API timing and build duration are workstation evidence, not a hosted service-level objective.
- The AI fixtures protect contract boundaries rather than general semantic accuracy.
- Accessibility automation does not replace assistive-technology testing with real users.
- Hosted alerting, W3C distributed tracing, backups and disaster recovery remain deployment work.
