# v1.2 AI Evaluation Evidence

## Boundary Under Test

OpsPilot evaluates whether a recommendation payload obeys the application contract before persistence. The readiness engine is not part of the model output and remains authoritative.

## Committed Cases

| Fixture                      | Expected | Boundary                                                  |
| ---------------------------- | -------- | --------------------------------------------------------- |
| `valid-grounded-blocker`     | Accept   | Valid proposal cites supplied readiness evidence          |
| `reject-ungrounded-evidence` | Reject   | Unknown evidence key cannot introduce a new product claim |
| `reject-extra-field`         | Reject   | Unsupported fields cannot bypass the contract             |
| `reject-duplicate-keys`      | Reject   | Stable recommendation keys must be unique                 |
| `valid-no-action`            | Accept   | A model may conclude that no advisory action is needed    |

Result: **5/5 fixtures pass** through both the evaluation API and Jest suite.

## Failure Behaviour

The provider path falls back to deterministic recommendations when it is disabled, lacks a key, times out, refuses, returns an HTTP error, returns no text, or fails schema/grounding validation. The run stores `provider=DETERMINISTIC`, `status=FALLBACK` and a user-readable reason.

## Limitations

- These fixtures test structural and grounding controls, not broad model quality.
- They do not simulate prompt injection inside future untrusted content fields.
- A production rollout needs labelled domain cases, model/version comparisons, cost and latency thresholds, and sampled human review outcomes.
